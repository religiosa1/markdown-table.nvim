1. Markdown Table                              *markdown-table-markdown-table*

Neovim plugin for some actions for editing markdown tables.

It provides actions to:

- Delete columns, optionally cutting them into a register
- Paste columns from a register (auto-expanded to the target table’s size)
- Add blank columns
- Generate a table stub of provided width/height
- Convert a table to TSV and back, in place or into a register, for ease of
    pasting tables from a webpage or a DB export, or pasting them into a spreadsheet

It only provides actions for the tables editing and TSV import/export, nothing
else. All actions can be undone.

For the full smorgasbord of various markdown editing actions (including table
edits) look at markdown-plus
<https://github.com/YousefHadder/markdown-plus.nvim>.

I prefer my plugins to be smaller in scope, and I don’t need most of the
features of that plugin, and want to avoid potential interactions with other
rendering and editing plugins, hence this.


WHY NO ADD/DELETE ROWS?

Because it’s basically just add or delete a line and a bunch of `|` inside, I
don’t see it’s worth it. Just do `dd`/`o`/`O`.


HOW IT WORKS?                    *markdown-table-markdown-table-how-it-works?*

This plugin uses treesitter to get the position of a nearest table in a
markdown document. The rest of logic is basically splitting/joining by the `|`
character. There’s some limited support for escaped `\|` in cells.


REGISTERS ~

Cut columns are stored in a register as a borderless sub-table, one row per
line.

This allows you to move the columns around, e.g. if you want to swap to columns
around, you can do "delete" and "paste after", mirroring `x` and `p` for
characters in vim itself.

Cutting the middle column of

>
    | Header 1 | Header 2 | Header 3 |
    | -------- | -------- | -------- |
    | Foo      | Bar      | Biz      |
<

puts this into the register:

>
     Header 2
     --------
     Bar
<

Cutting last two columns puts this:

>
     Header 2 | Header 3
     -------- | --------
     Bar      | Biz
<

Pasting splits it back on `|` and inserts it as column(s), expanding cells to
the target table’s height and width. So you can cut a column from one table
and paste it into another of a different size.

Both `delete_column`’s `to_reg` and `paste_column`’s `from_reg` accept:

- a register name (`"+"`, `'"'`, `"z"`, …)
- a list of register names (`{ '"', "+" }`) — `delete_column` writes to all of them
- `true` — route by `'clipboard'`: `+` when `unnamedplus` is set, `*` when
    `unnamed` is set, and always the unnamed `"`. Pasting reads the first non-empty
    one in that order. This is the recommended value: a cut then reads back from
    wherever your `p` pastes from, so it works whether or not you have
    `clipboard=unnamedplus`.

Omitting `to_reg` deletes without cutting; omitting `from_reg` adds a blank
column.

Pasted content without a header separator on its second line (e.g. a column
copied from a doc or a spreadsheet) gets one added, so no cell is lost under
the table’s separator row. `paste.missing_separator` picks what the first
line is: `"header"` (default) makes it the column’s header, `"body"` adds a
blank header and pastes every line into the body.


TSV ~

Copying a table from a webpage, a spreadsheet or a DB client usually gives you
tab-separated values. `convert_table` turns them into a markdown table in place
(and a markdown table back into TSV); `yank_converted` puts the conversion into
a register without touching the buffer.

The first TSV row becomes the table header, unless the TSV sits inside a
table’s body or right below it: then `convert_table` (with auto direction)
turns it into body rows only, as rows pasted into that table. Markdown to TSV
keeps the header and drops the separator row (and its alignment). `|` in cells
is escaped/unescaped. No TSV quoting is supported: cells are split on tabs as
is.

Both act on the visual selection, or, without one, on the markdown table under
the cursor, or the block of lines containing tabs around it.

`yank_converted` reports how many lines it yanked; `no_notify = true` silences
it. The message is configurable with `yank.message` (see Configuration).

`skip_header = true` drops the header row when converting to TSV, e.g. to
append rows to an existing spreadsheet.

Direction is detected from the content (a markdown table if the first line
starts with `|`, TSV otherwise), or forced with `direction = "to_tsv"` /
`"to_markdown"`. `yank_converted`’s `to_reg` takes a register name, a list of
names, or `true` (the default, routed by `'clipboard'`) like
`delete_column`’s.

For scripting, `convert_lines(lines, { direction = ..., skip_header = ... })`
returns the converted lines.


INSTALLATION                      *markdown-table-markdown-table-installation*


LAZY: ~

(require is inside of handler, to ensure proper lazy loading)

>lua
    {
      "religiosa1/markdown-table.nvim",
      lazy = true,
      ft = { "markdown", "text", "plaintext" },
      keys = {
        {
          "<leader>jtt",
          function()
            require("markdown-table").create_table()
          end,
          mode = { "n" },
          desc = "Create a markdown table",
        },
        {
          "<leader>jtd",
          function()
            require("markdown-table").delete_column { to_reg = true }
          end,
          mode = { "n", "x" },
          desc = "Cut a markdown table column",
        },
        {
          "<leader>jtD",
          function()
            require("markdown-table").delete_column()
          end,
          mode = { "n", "x" },
          desc = "Delete a markdown table column without cutting",
        },
        {
          "<leader>jtA",
          function()
            require("markdown-table").paste_column { paste_mode = "before" }
          end,
          mode = { "n" },
          desc = "Add a markdown table column before",
        },
        {
          "<leader>jta",
          function()
            require("markdown-table").paste_column { paste_mode = "after" }
          end,
          mode = { "n" },
          desc = "Add a markdown table column after",
        },
        {
          "<leader>jtP",
          function()
            require("markdown-table").paste_column { paste_mode = "before", from_reg = true }
          end,
          mode = { "n" },
          desc = "Paste a markdown table column before",
        },
        {
          "<leader>jtp",
          function()
            require("markdown-table").paste_column { paste_mode = "after", from_reg = true }
          end,
          mode = { "n" },
          desc = "Paste a markdown table column after",
        },
        {
          "<leader>jty",
          function()
            require("markdown-table").yank_converted { direction = "to_tsv" }
          end,
          mode = { "n", "x" },
          desc = "Yank TSV representation",
        },
        {
          "<leader>jtY",
          function()
            require("markdown-table").yank_converted {
              direction = "to_tsv",
              skip_header = true,
            }
          end,
          mode = { "n", "x" },
          desc = "Yank TSV without header",
        },
        {
          "<leader>jtc",
          function()
            require("markdown-table").convert_table()
          end,
          mode = { "n", "x" },
          desc = "Toggle between TSV and a markdown table",
        },
      },
    }

CONFIGURATION                    *markdown-table-markdown-table-configuration*

All configuration values are optional and provided here only for the reference

>lua
    {
        new_table = {
            prompt = "Enter table size",
            default_n_lines = 0,
            max_width = 30,
            max_height = 50,
            -- header text of generated columns: a format string (%d is the column
            -- index, omit it for no index) or a function `fun(idx): string`
            header = "Header%d",
        },
        -- column added by paste_column without from_reg
        new_column = {
            header = "Header", -- same format as new_table.header
        },
        paste = {
            -- pasted content without a header separator (e.g. from google docs):
        -- "header" (first line is the header) or
        -- "body" (blank header, all lines go into the body)
            missing_separator = "header",
        },
        yank = {
            -- notification after yank_converted; return nil to skip it.
            -- info: { count, direction = "to_tsv" | "to_markdown", skip_header }
            message = function(info)
                if info.direction == "to_markdown" then
                    return string.format("Yanked %d markdown table lines", info.count)
                end
                local header = info.skip_header and "without" or "with"
                return string.format("Yanked %d TSV lines %s header", info.count, header)
            end,
        },
    }
